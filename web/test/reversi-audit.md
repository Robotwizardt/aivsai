# 黑白棋浏览器验收记录

日期：2026-10-13。环境：本地 Edge、前端 Vite 生产构建 preview、后端 `node dist/index.js`、独立 SQLite 内存库。未部署公网、未访问生产数据库。测试凭据不写入记录。

## 发现与修复

| 编号 | 复现与影响 | 原因与修复 | 回归证据 |
| --- | --- | --- | --- |
| R1 | 创建后复制任一座位链接，只得到 `#/seat/<REDACTED>`，无法直接发给站外 AI | 前端直接复制 API 相对片段；改为按当前页面 URL 构造完整 hash 路由，保留 origin、端口及页面路径，并编码座位标识 | `reversi-lifecycle.js` 实际读取两个复制按钮写入的剪贴板，修复前均失败，修复后均通过 |
| R2 | 复制观战链接只得到 `#/match/...` | 展示和复制均改为完整 URL，编码 matchId | 同脚本验证实际剪贴板内容，红→绿 |
| R3 | 创建者暂停后，座位 API 返回 paused/409，但游客仍看到“直播中”和“轮到落子” | 公共比赛 phase 在暂停时仍为 running；观战页补读表演赛 paused 元数据，暂停时关闭直播点和轮次提示；结束状态优先 | 同脚本在独立游客 context 验证暂停、恢复，无需刷新；暂停两条断言红→绿 |
| R4 | 首次修复审查发现：若摘要或暂停元数据请求挂起，另一接口已成功的结果也不更新 | Promise.allSettled 仍等待全部请求完成；改为独立轮询、独立应用结果，每请求 5 秒取消，卸载清理请求与计时器 | `board-polling.js` 两个方向的挂起回归均先失败，再全部通过 |

R1 初步曾误判为后端端口问题；复核确认是相对片段直接复制，已更正，不修改服务端 URL 协议。

## 通过范围

- `reversi-lifecycle.js`：28 项真实浏览器检查通过；复制链接、两座位命名、非轮次与暂停行动拒绝、游客暂停恢复、SSE 更新、直播回看不被新帧打断、回到最新、刷新棋谱、解散、私密列表隔离、私密凭链接观战、累计三错判负、无未捕获浏览器异常。
- `board-polling.js`：两个接口挂起隔离检查通过。
- `reversi-e2e.js`：按独立规则校验每步合法点与棋盘，60 手完成，自动跳过 4 次，黑 19／白 45，白胜；刷新回放、逐帧、播放暂停、终局通过。四主题 × 375/900/901px 共 12 组真实终局布局无整页横向溢出。
- 后端全量：259/259；前后端类型检查及构建通过。

测试脚本也修正了两处测试自身的问题：游戏 label 包含选项文本，改为前缀匹配；写入测试登录态后完整刷新页面。生命周期异步断言改为有界条件等待，回看断言先确认新帧已到达（回放进度上限增长），避免空等误判。

## 边界

- 双座位提交使用确定性脚本 Agent，不代表调用了两个外部大模型；未验证外部模型策略强度或供应商网络。
- 挂起场景由浏览器网络拦截模拟；未穷尽丢包、长时间并发、多浏览器兼容及公网代理配置。
- 本次修复不改依赖、数据库 schema 或 CI；未 commit/push。
