# 账号密码体系取代无账号凭证体系

平台从「邀请码兑换工作台、凭证管理一切」的无账号体系（ADR 0002）转向账号密码体系：注册必须填写管理员发放的邀请码，用户名密码登录，`users` 表取代 `workspaces` 表，「工作台」概念并入「用户」。直接动因是表演赛（ADR 0017）需要稳定的创建者身份与管理权（暂停、解散、重发座位密钥），凭证体系下只能靠一次性 creatorKey 补丁，长期会演变成两套并存的创建者识别机制；既然要动鉴权，就一步到位换成账号体系。

## 账号与登录

- 注册必须填写有效邀请码（邀请码保留，语义从「兑换工作台」变为「兑换注册资格」），邀请码仍由管理员发放、一次性作废。
- 密码哈希存储；登录签发 Bearer 会话令牌（sha256 存库、可随时吊销），前端沿用 localStorage + `Authorization` 头的形态，`api.ts` 与各页面改动最小。
- 找回密码：注册时另行提供恢复码，凭恢复码自助重置；两者均丢失时由管理员在后台兜底重置（生成一次性新密码转交），仍不行只能重新注册。
- 单角色管理员：`users.role`（`user` | `admin`），首个管理员由环境变量种子初始化；管理员可提升/降级/封禁用户（封禁用户无法登录，数据保留）。不做超管层级，不做细粒度权限点。

## 数据与术语

- 存量 workspaces / credentials / recovery_codes 数据清零重来，不写迁移脚本（项目尚在开发期，无真实用户数据需要保留）。
- 术语表删除「工作台」「工作台凭证」「对象凭证」「管理凭证」，新增「用户」「管理员」「API 令牌」等条目；`entrants.workspace_id` 改为 `user_id`。
- 面向 AI 的鉴权保留为 API 令牌（双轨制），见 ADR 0016——账号体系只取代面向人的凭证，不能一刀切取消全部 token，否则外部 Agent 无法调用平台 API。

## 实施顺序

账号系统先行落地并验收，表演赛机制（ADR 0017）与象棋（ADR 0018）随后，分三个可验收阶段；不与大爆炸式一次性交付。

## 被取代的决策

本 ADR 取代 ADR 0002 的全部凭证体系设计：工作台兑换、工作台凭证、对象凭证、凭证恢复流程、恢复码绑定工作台的语义。ADR 0002 中「邀请码控制创建资格」「策略源码可见范围」「训练对手范围」等与鉴权载体无关的决策继续有效，仅将「工作台」读作「用户」。
