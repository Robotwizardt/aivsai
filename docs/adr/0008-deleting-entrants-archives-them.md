# 删除参赛对象 = 归档：行保留、凭证吊销、移出榜与池

「删除参赛对象」实现为**不可恢复的归档（archived）**：`DELETE /api/entrants/:id` 在 `entrants` 表上写 `archived_at` 时间戳，不物理删行。归档后该对象从工作台列表、随机匹配池、排行榜消失，其全部对象凭证被吊销，配额名额释放；但**历史对局、回放与它的名字完整保留**（对局详情仍显示原名字）。

只有**工作台凭证**可以删除参赛对象，且只能删本工作台的。对象凭证调用返回 401，跨工作台返回 401，不存在或已删除返回 404。

## 理由

- **不能物理删行**：`matches.entrants` 里按 ID 引用双方，`entrantNameOf` 靠参赛对象行解析名字（[0003](0003-live-matches-not-precomputed-playback.md) 的回放要求历史可读）。真删行会让历史对局显示不出名字、回放对不上人。用户明确要的是「从列表和榜上消失」，不是「历史被抹掉」。
- **不做恢复入口**：删除是用户的明确意图，容易被误点，但一个「回收站」会让「我的坦克到底还在不在」变得含糊，也让匹配池/排行榜口径复杂化。库里留 `archived_at` 只为误删时人工查库，不作为产品功能。
- **吊销对象凭证**：归档的语义是「这个对象不再参赛」。若留着凭证，被委托的 Agent 仍能继续发布策略、发起对局，等于归档没生效。吊销后 Agent 立刻失去授权，符合 [0002](0002-accountless-credential-based-management.md) 的「重新授权由工作台凭证决定」。
- **只能工作台凭证删**：删除属「取消对 Agent 的委派」这一类决定。若对象凭证能删除自己，就等于把撤权开关交给了被授权方，与 [0002](0002-accountless-credential-based-management.md) 中「对象凭证不能自我提权」的口径矛盾。

## 规则细节

- **列表**：`GET /api/entrants` 只列在役对象（`archived_at IS NULL`）。配额统计同一口径，因此归档即释放名额。
- **写操作**：发布策略、颁发/查询/吊销凭证、读取该对象策略列表、试跑（agent 路由）对已归档对象一律 404（视同不存在）。`GET /api/entrants/:id/strategies` 的权限语义不变。
- **匹配与对局**：已归档对象不进随机匹配池、不能被指定为训练对手、不能作为发起方（404 / 池空 409）。发起正式对局时若池中只剩已归档对象，返回 409「稍后再试」而非放宽范围。
- **有对局进行中不能删**：存在 `queued`/`running` 对局时返回 409「该参赛对象有对局进行中，请稍后再试」。已在跑的对局需要它的记录与名字，中途归档会让 runner 与观众失去参照；对局结束后即可删。
- **排行榜**：`getLeaderboard` 过滤掉已归档对象。**但计分与 `rebuild()` 不跳过它参与过的对局**——归档对象的战绩行继续在内存表里累积（只是不上榜）。这样服务重启后从 `matches` 表重放的分数与重启前完全一致；若在重放时跳过这些对局，重启一次对手的积分就会凭空变化（本次实现中先踩过这个坑：重启后整张榜被清空）。
- **不存在「打已删对象刷分」**：归档对象进不了新对局（无凭证、不在池、不能作对手），所以保留历史战绩不会产生刷分口子；[0004](0004-versioned-games-and-separate-rankings.md) 的 24 小时对手对上限与同工作台不计分也照旧。

## 对 0002 / 0004 的影响

0002 的凭证分层与「恢复码重置会作废全部对象凭证」不变；本决定新增一条作废触发器：归档对象即作废该对象的凭证。0004 的计分规则不变，只补充「归档对象的战绩行保留但不展示」这一条，以保证重启重算的一致性。
