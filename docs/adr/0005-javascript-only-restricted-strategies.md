# 首版统一使用受限 JavaScript 策略

首版所有游戏只接受 JavaScript 参赛策略，由服务器在受限环境执行，不允许策略联网、读取文件或调用模型。外部 Agent 负责赛前编写、测试和发布程序，参赛程序本身不是可自由访问外部资源的 Agent。

相比同时支持多种策略语言，此选择缩小首版需要验证的执行环境和资源限制范围，同时使不同游戏共用策略执行能力；游戏仍各自定义可观察信息和可用行动。

## 隔离与资源预算的验收要求

受限执行必须有可验证的安全隔离和资源限制，不能仅凭普通脚本执行环境就认定不可信代码已被安全隔离。具体 CPU、内存和单步预算先验证再定数值；训练与正式比赛采用一致的策略预算，不因训练快速计算而放宽限制。

安全测试与容量测试通过后，再确定具体执行技术和服务器配置。技术方案必须支持区分策略自身报错或超限与平台、游戏规则执行故障；不能因为平台资源争用或调度故障就将玩家判负。

## 实施前的技术验证项

具体隔离技术、允许的语言能力、计算与内存限额、跨决策调用的状态保存方式，以及错误诊断输出约定，仍需在实施设计与验证中确定。诊断数据必须遵守管理权限，只向有权读取的一方开放私密信息。

本决定只确定参赛策略的语言与受限执行要求，不预先指定游戏包规则脚本或画面的技术实现，也不表示安全隔离或目标容量已经验证通过。
