# 表演赛：邀请外部 AI 直接对弈的第三种对局

新增第三种对局类型「表演赛」，与正式对局、训练并列：由登录用户创建一场指定游戏的对局，平台生成红/黑两个座位链接（`#/seat/<token>`，链接内嵌座位密钥），人把链接发给两个外部 AI；AI 通过 HTTP API 轮询当前局面、提交行动，一场一局轮流进行，全程可直播。对局创建时锁定的是「座位」而非策略版本——这是与现有对局的根本区别：现有体系里策略源码在开赛前注入沙箱执行，表演赛的座位则在对局进行中通过 API 逐手接收外部 AI 的行动。

机制做成游戏无关的通用层（临时座位凭证 + 行动提交协议 + 生命周期管理），象棋（ADR 0018）是第一个接入的游戏；引擎只需把 `EntrantHandle.act` 的实现从「QuickJS 沙箱回调」替换为「等待外部 HTTP 提交」的适配器，平台核心循环（MatchRunner、LiveHub、SSE 直播、回放落库）全部复用。

## 创建与可见性

- 登录用户才能创建（每用户同时最多 3 场未结束表演赛、全站同时最多 30 场，超限 429）；观战、座位页、AI 调座位 API 免登录。
- 创建时可选标题（默认自动生成）、可选每步时限（默认 30 分钟）、默认公开可选私密。私密表演赛不进任何列表，但知道对局链接（`#/match/:id`）即可观战。
- 创建产出红/黑两个座位链接，管理权天然归属创建者账号（无账号补丁 creatorKey），暂停/恢复/解散由创建者与管理员可用；管理员在 AdminPage 集中管理全部表演赛（含私密）。

## 座位协议

- AI 用座位密钥调 REST API：查询当前局面 → 提交行动（走法格式由游戏定义，象棋为 `{from:[x,y], to:[x,y]}` 0 基坐标）→ 未轮到时 API 返回可重试状态。
- 非法行动返回 400 + 具体原因，AI 可立即重试；连续 3 次非法判负（与五子棋错误上限一致）。
- AI 首手可自报名称（如 `DeepSeek-R1`），直播页与对局列表显示该名称，不报则默认「红方/黑方」。
- 座位密钥不随对局结束失效，而是进入「观察期」：结束后（含解散、作废）凭原密钥 `observe` 仍返回 `status: finished` 与终局信息（作废时附 `hint: 对局已作废`），外部 AI 据此自行收摊；此时提交行动由 409 拦下（未轮到 / 暂停 / 已结束同用 409，401 只表示密钥本身无效）。座位页 v1 只读（局面 + 密钥 + API 文档），不提供人工落子交互。
- `observe.moveCount` 是**真实手数**（已接受的行动数）：被拒绝的行动（非法走法、每步超时）不计，也不等于帧数（拒绝同样产帧）。回合制游戏的帧 `state` 必须携带同口径的 `moveCount`（GamePackage 契约 `TurnBasedFrameState`），座位页与观战页直接显示该值。

## 生命周期

- 每步时限超时判负；创建后 1 小时无第一手自动作废；创建者/管理员可暂停（冻结全部计时，座位 API 返回 paused 状态、提交行动返回 409，文档指引 AI 等待后重试）或解散。
- 结束后永久保留可回放（与正式对局一致），对局列表带「表演赛」标记。
- 表演赛不计分：不进排行榜、不影响任何参赛对象的积分（临时座位没有参赛对象身份，Elo 无从附着）。

## 被否的选项

- SSE 推送「轮到你了」：现实中外部 Agent（Claude/GPT 等）对 SSE 长连接支持很差，轮询对 AI 要求最低。
- 人传话界面（复制局面给 AI / 粘贴回复）：对无网络工具的 AI 友好，但人要来回搬运，不满足「AI 自己下」的定位。
- 座位页支持人工落子：无法区分「AI 下的还是人下的」，交互棋盘留待 v2 顺便解锁人机对战。

## 修订

- 2026-10-12：座位密钥改为「观察期」（原文「一次性密钥，对局结束即失效」作废）。原设计下对局一结束密钥即被删除，外部 AI 拿到 401 既拿不到终局也分不清「对局已结束」与「密钥配错了」，收摊无从判断；改为结束后仍可 observe 终局状态、由 409 表示不能再出手。
