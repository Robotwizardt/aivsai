# 匹配池不区分工作台，同工作台对局不计分

正式随机匹配的候选池**不再排除同工作台的参赛对象**：同游戏、非自己、有已发布策略、积分差 ≤ ±50 的对象一律进池，等概率随机选中。训练指定对手同样允许同工作台对象，仍然禁止与自己对战。

这是对 [0006](0006-official-random-matchmaking.md) 中「非同工作台」候选条件与「训练不能挑战同工作台对象」两条限制的**显式修正**。0006 其余决定（只有正式对局随机匹配、±50 分差窗口、池空 409 不放宽、训练必须指定对手）继续有效。

## 理由

0006 排除同工作台的目的写在理由里是「防止自己控制的对象互相做局」，但这道防线其实由别处承担：

- **同工作台对局本来就不计分**（[0004](0004-versioned-games-and-separate-rankings.md)）：`RankingService` 在结算前比对双方 `workspaceId`，相同则整场跳过。做一个不计分的局，刷不出任何分。
- 真正防刷分的是「只能随机匹配 + 对手积分与自己相近 + 同台不计分」，与工作台隔离无关。

而排除同工作台带来一个实际故障：**单人 / 早期部署下正式对战池恒空**。平台刚上线时只有自己的一个工作台有已发布策略，其他工作台还没发布任何东西，于是随机匹配必然 409，正式对战「一点也用不了」。训练对局里禁止同工作台更矛盾——训练本来就不计分，禁止它没有任何收益，只让用户无法拿自家两个对象对练。

## 规则细节

- **正式（official）**：候选池 = 同游戏 ∧ 非自己 ∧ 有已发布策略 ∧ 积分差 ≤ ±50。**不按工作台过滤**。池为空仍返回 409 并提示稍后再试，不放宽范围。
- **训练（training）**：指定对手可以是同工作台或其他工作台的任意参赛对象（对方需有已发布策略），也可以是内置 bot；唯一禁止的是「与自己对战」。
- **计分**：同工作台对局照旧跳过计分（0004）。因此排行榜只反映跨工作台战绩，同台对局只进对局记录与回放。
- 建库层面的同工作台上限（每工作台对象配额）不受影响。

## 对 0004 / 0006 其他内容的影响

0004 的「同工作台对局不计分」「同一无序对手组合 24 小时内最多 3 场计分」不变，且「同工作台不计分」现在不再与正式匹配池冲突——同台对局是正式对局池的正常一部分，只是不计分。0006 关于「正式只能随机匹配、训练可指定」的大方向不变。
