# 宽屏 fluid 布局：应用页铺满全宽，登录态首页 dashboard 两列一屏化

此前应用页容器 `#root` 统一限宽 1120px，在 ≥1440px 的宽屏上左右出现大片空白；登录态首页纵向堆叠（横幅/我的游戏/最近对局），宽屏下一屏看不全。用户反馈「电脑横屏 UI 没适配，两边好多空隙，要饱满点，功能一屏显示完 Y 轴不用动」。

我们决定：宽屏模式（≥901px）下应用页取消 1120px 限宽，铺满全宽（fluid）；登录态首页改为 dashboard 两列布局——工作台横幅横贯顶部，左列「我的游戏」自适应卡片网格，右列「最近正式对局」20 行/页表格区内滚，整页锁视口高、页面 Y 轴不动。

相比维持限宽或为超宽屏单独设计一套布局，fluid + 列宽上限的组合只改容器与网格，页面代码不变，各页面自动受益（管理页表格、工作台分栏随列伸展）；代价是长文阅读页（Agent 指南）与代码编辑器在超宽屏上行长过长影响可读性，需要保留限宽例外。

## 规则

- `#root` 限宽 1120px 仅对无 `.app-page` 的页面（游客态落地页）保留，且落地页本就另有 1440px 营销限宽。
- 应用页（`.app-page`）宽屏下 `max-width: none`，`body:has(main.app-page)` 提高优先级压过旧的 workspace 限宽规则。
- 例外限宽：Agent 指南（`.app-page--narrow`，1080px 居中，长文阅读）；工作台策略编辑器 `.editor` 上限放宽至 1400px（代码行可读性）。
- 登录态首页：`home-dash` 网格 `grid-template-columns: minmax(320px, 5fr) 8fr`；右列对局表容器 `.matches-scroll` 内滚，pager 钉在列底。
- 手机模式（≤900px，ADR 0013）不受影响：`home-dash` 退化单列自然流，`matches-scroll` 不滚。

## Consequences

- 宽屏应用页不再有两侧空白；同一页面代码双端复用。
- 观战/回放页也走 fluid：内容本就超一屏，整页区内滚让 canvas 用自然大尺寸（ADR 0011 的锁视口高策略不变）。
- 管理页、游戏详情页卡片网格 `auto-fit` 自适应铺开，不随屏幕加宽而闲置。
