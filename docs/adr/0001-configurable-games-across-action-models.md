# 后台新增游戏，并覆盖即时与回合制规则

平台首款完整游戏为坦克大战，新增游戏通过后台导入 AI 按约定编写的游戏包完成。游戏包可以包含规则脚本、配置、画面和说明；接受新游戏自身需要编程，但新增符合约定的游戏不应要求修改平台核心，也不以建设万能无代码规则编辑器为目标。

扩展范围既包含坦克式即时战斗，也包含棋类回合制，因此游戏规则不能与坦克特有的行动和状态绑定。首版额外交付最小五子棋实例，验证游戏导入、策略接入、对战和回放，而不是仅凭坦克的实现推断扩展能力；五子棋不要求与坦克同等精修。

相比固定模板改参数，此方案允许表达更多规则；相比为每款游戏修改平台，它把游戏差异集中在游戏包中，但需要明确并验证包的兼容约定与执行权限。

## 导入与展示

管理员在后台导入游戏包，经过校验和预览测试后直接启用，不要求重新构建或部署整个平台。游戏包自带二维画面，平台统一提供播放、暂停、进度和结果界面；游戏包不能任意接管整个网站。相比预置模板或静态部署，这保留了新游戏的规则与画面表达能力，但需要对动态加载的内容进行兼容性检查和权限隔离。

## 平台与游戏包的职责边界

采用通用对战平台加游戏包的结构，不先把平台与坦克规则绑定，再依赖后续重构增加其他游戏：

- 平台核心负责工作台、凭证、策略版本、排队、排行榜、历史记录和外部 Agent 接口。
- 游戏包负责该游戏的规则、地图与技能、合法行动、胜负判定、二维画面和策略编写说明；棋类游戏不必具有坦克的地图或技能概念。
- 隔离运行服务负责执行规则和策略、限制资源，并区分策略故障与平台或游戏规则故障。
- 观看界面统一提供直播、暂停、进度和回放控制，加载对局所绑定版本的游戏画面。

这些是职责边界，不预先指定框架、数据库或具体隔离技术。

## 首版扩展边界与验收

首版游戏包协议覆盖双人、二维、即时制和回合制游戏。符合协议的包经过校验和预览后可以动态启用，不修改平台核心、不重新构建或部署平台；三维、大规模多人等超出协议的能力可能需要扩展核心，不承诺支持任意游戏。

必须在不修改平台核心的前提下，通过后台导入最小五子棋游戏包，实际跑通策略提交、对战和回放。仅有接口定义或坦克内部的不同地图，不视为通过跨游戏扩展验收。

## 首版产品边界

坦克首版交付创建与管理、技能和地图、策略编辑与版本、模拟训练、1v1 对战、排行榜、历史回放及外部 Agent 接口，不将多人混战、团队战、Raid、杯赛或社区商店作为首版要求。AI 在平台外编写和改进策略，网页保留手动编辑入口，不建设网页内置 AI 助手。

玩法和主要使用流程参考目标网站，采用原创品牌、布局和素材，不要求逐像素还原。坦克支持预置造型、颜色、名称及自定义图片上传，外观不改变战斗属性；首版不内置付费图像模型调用。电脑端支持全部操作，手机端主要用于浏览游戏、排行、直播和回放，不要求完整策略编辑或游戏包管理。界面、入门说明和错误解释以中文为主，代码标识符保留英文，不提供语言切换。

## 实施前的技术验证项

具体包格式、规则与画面接口、允许的脚本能力、隔离技术和兼容检查清单仍需在实施设计与验证中确定，不属于已经实现或测试通过的能力。坦克的具体地图、技能数值与规则细节需要形成可验收的规则清单，不能仅以“与参考网站相同”作为实现依据。
