# 排行榜与对战历史显示「坦克名@工作台名」，工作台名唯一且可改名

排行榜原来只显示参赛对象 id 前缀，对战历史只显示名字（重名时分不清是谁家的），工作台也没有改名入口。我们决定：参赛对象 `name` 不加唯一约束（允许多个坦克同名），展示侧统一用「坦克名@工作台名」消歧；内置 bot 不属于工作台，只显示「名字（内置基准）」不加 @。为支撑消歧，工作台 `nickname` 必须**唯一**且**可改名**：应用层 create/rename 查重给友好报错，数据库加 `UNIQUE` 索引（null 除外）双保险；改名撞名直接拒绝提示「该名字已被占用」。无昵称的工作台在迁移时自动起名「工作台-<短随机后缀>」保证唯一（用户可自行改成好听的名）。改名**即时生效**——名字是运行时查的而非快照，故历史对局与排行榜自动显示新名。

## Consequences

- 后端：`workspaces` 加唯一索引迁移 + 启动时给 null 昵称自动起名；`WorkspaceService` 加 `rename`（查重）与「读自己工作台信息」能力；新增改名路由（如 `POST /api/workspaces/me/nickname`）与自信息路由（`GET /api/workspaces/me`）；排行榜路由层把内存榜单 join `entrants→workspaces` 补 `name`/`workspaceNickname`；`matchSummary` 的 `entrants` 补 `workspaceNickname`。
- 前端：排行榜、对战历史（游戏页/首页/工作台三处）、观战页统一显示「坦克名@工作台名」；首页横幅与 WorkspacePage 顶部显示昵称+改名入口；对战历史加类型/参赛对象/游戏筛选（后端已支持 gameId/kind/entrantId，纯前端控件）。
- 历史对局的「@工作台名」不是快照——这是有意的：改名即时生效保持体验一致，代价是历史显示的是「现在」的工作台名而非当时名。
- 数据库迁移需先给既有 null 昵称生成唯一名，再建唯一索引，顺序不可颠倒。
