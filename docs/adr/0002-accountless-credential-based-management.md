# 公网共享但不建立用户登录体系

首版通过公网网址供熟人使用，不建立账号登录体系。各参赛对象的管理权由私密管理链接或密钥证明，持有者及获授权的外部 Agent 可以修改，并以自己的参赛对象发起挑战；无凭证的访客只能观看。相比所有人可任意修改，这保留了管理边界；相比账号体系，这减少了使用步骤，但管理凭证泄露就可能导致相应控制权泄露。

## 创建资格与后台权限

平台所有者发放的一次性邀请码兑换一个私密工作台，工作台可跨已开放的游戏创建多个参赛对象，数量受管理员设置的配额限制。邀请码不限定单一游戏，也不等于只授予一个参赛对象的名额；访客不能仅凭公开网址无限创建和提交程序。后台新增游戏和调整平台设置使用独立管理员密钥，该密钥不与工作台或参赛对象管理凭证混用，不引入用户账号体系。

## 私密工作台与分级授权

朋友兑换邀请码后获得自己的私密工作台及工作台凭证，统一管理多个游戏中的参赛对象，而不是分别保存互不关联的对象管理入口。交给外部 Agent 的凭证仍限定到指定参赛对象，不因此获得整个工作台或平台后台的管理权。

## 策略源码的可见范围

策略源码默认私密，只有管理者及获授权的 Agent 可以读取；管理者可以主动公开某个策略版本。对局回放和面向他人的错误信息不得意外泄露私密源码。源码公开是版本级选择，不能因查看公开战绩而推定有权读取未公开策略。

## 发起正式对局与信息可见范围

正式对局只能由持工作台凭证或对应对象凭证的人及外部 Agent，以其有权管理的参赛对象发起；对手无需在线。无凭证访客只能观看，不提供访客撮合正式计分比赛或表演赛的入口。

观众可在正式对局直播和回放中查看完整战场，但策略只能收到规则允许的信息，不能借观战数据绕过草丛等隐藏信息规则。私密策略源码和调试日志不向观众公开，平台需要区分观战数据、策略观察数据和管理者诊断数据。

管理者只能读取自己有权管理一方的私密诊断。发起一场挑战或训练，不因此获得对方的私密源码或调试日志；不能把“有权查看该对局”当成“有权读取双方私密数据”。

## 训练对手范围

自己的未发布候选策略可以选择己方有权管理的策略版本、内置基线，以及其他可挑战对象的当前已发布策略作为训练对手。对方程序由平台代为执行，即使其源码私密也可以作为上述训练对手，但不因此开放其源码和私密日志。训练默认私密且不计排名。

相比仅允许训练公开源码策略，此选择让参与者能在发布前评估与实际对手的对抗表现，同时保留对手程序的读取权限边界。

## 工作台凭证恢复

创建工作台时另行提供恢复码；工作台凭证丢失后，持有恢复码的人可以自助更换凭证，不增加邮箱或短信找回流程。凭证和恢复码均丢失时不承诺找回，不将管理员人工重置作为默认恢复方式。这个选择保留无账号使用方式，但要求参与者另外保管恢复码。

恢复工作台时，旧工作台凭证、既有工作台会话及该工作台下全部对象凭证一并失效，同时更换恢复码，旧恢复码不再可用。外部 Agent 必须重新获得授权；已创建的比赛不因凭证恢复而改判。

相比保留对象凭证，此选择优先恢复完整控制权，代价是中断既有 Agent 的后续管理访问，不能将仅更换工作台密钥视为完成恢复。

## 实施前的技术验证项

凭证的具体传递与存储方式、撤销和恢复操作的一致性、工作台默认配额及挑战和训练的具体消耗限额，仍需在实施设计与验证中确定。“不登录”不表示所有管理操作都公开，也不表示这些安全机制已实现。

## 实施补充：对象凭证明文存库

实施后修订（2026-10）：**对象凭证的明文与哈希一并存入数据库**，工作台凭证持有者可通过 `GET /api/entrants/:id/credential` 随时取回明文——因为该凭证的用途就是复制给外部 Agent，「只展示一次」迫使用户在颁发瞬间完成复制，实际使用中（刷新页面、换设备、忘记保存）频繁造成「只能重新颁发」的打扰，反而诱导用户把凭证随手贴在聊天工具里。

风险接受：能读数据库的人（即部署者本人）可拿到所有对象凭证明文。这个风险等级与「部署者能改代码 / 直接读库颁发凭证」相同，不扩大威胁面。工作台凭证与恢复码仍只存哈希（它们丢失要走恢复流程，不是日常复制对象），不变。
